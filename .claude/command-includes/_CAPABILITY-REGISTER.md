# Capability register

Status: APPROVED IN PRINCIPLE by Andrew 2026-10-23 ('good sort that'). Routes and precedence are in force. The decisions block is advice: no plugin has been enabled, disabled or removed yet. Source of truth: `capabilities/routes.json` in claude-system. Generated by `capabilities/inventory.py --render-register`; do not edit by hand.

Use this when choosing a skill, agent or tool. The model sees a long list of descriptions; this says which one WE prefer for a task shape.

## Precedence

- Operator instructions, CLAUDE.md, the gates and our slash commands outrank any plugin skill. A plugin skill that says to run 'before ANY response' (superpowers:using-superpowers) does not override SYSTEM mode, a command's phases or the skills gate.
- Our commands and viewports are the process. A plugin skill is technique used inside a phase, never a replacement for the phase.
- Where two capabilities overlap, use the one named in Routes and do not run both. Planning flows in particular: use /plan, /build-plan, /strategise, not superpowers:brainstorming or writing-plans.
- 'Verified' means what _VERIFICATION-STANDARD.md says, whatever a plugin skill claims about its own checks.
- Plugins marked project-only are not assumed to be loaded. Plugins marked review are not relied on or enabled for a task without asking.
- Capabilities flagged INBOUND, SHELL/BROWSER or AUTONOMOUS (imessage, desktop-commander, browser-use, ralph-loop) need Andrew's yes for each use.
- Every change still goes branch, PR, merge. A plugin that commits or pushes (commit-commands) is checked against protocols/how-we-work.md first.
